# yoriai
寄合システム

ローカルLLM対応デバイス(Mac mini, MacBook Pro, Mac Studioなど)が同一ネットワーク上で
自動的にお互いを発見し、各デバイスのスペックや利用可能なモデル情報を自律的に交換し合う
「組織」のようなエージェント群システムのプロトタイプです。

## 今回のスコープ

このプロトタイプは以下の2点のみを実装しています。

1. **自己紹介カードの生成**: デバイス名、OS/チップ情報、総メモリ/空きメモリ、
   Ollamaのインストール済みモデル一覧、ロード済み(メモリに乗っている)モデル一覧をJSONにまとめます。
2. **mDNSによる自動発見と自己紹介カードの交換**: 同一ネットワーク上の他のYoriaiエージェントを
   `zeroconf` (mDNS/Bonjour) で自動発見し、HTTP経由で自己紹介カードを取得してログに表示します。

タスクの割り振り、参加トークンによる認証、Ollamaの自動インストールなどは**次フェーズ以降**の対象です。

## 動作環境

- macOS (Apple Silicon) ※チップ情報・メモリ情報の取得は `sysctl` / `vm_stat` を利用するためmacOS専用です
- Python 3.9以降
- [Ollama](https://ollama.com/) がインストール済みで、`ollama serve` (通常は自動起動) が動作していること

## セットアップ

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## 実行方法

```bash
python3 yoriai.py
```

- 自己紹介カードをHTTPで配信するローカルサーバーが起動します(ポートは既定で自動選択)。
- mDNSに `_yoriai._tcp.local.` というサービスとして自分自身を登録します。
- 同時に、同じサービスタイプを名乗る他のエージェントをネットワーク上で探索します。
- 他のエージェントを発見すると、そのエージェントの `/card` エンドポイントにHTTPでアクセスして
  自己紹介カード(JSON)を取得し、以下のようにログへ表示します。

```
2026-08-18 10:00:00 [INFO] 🤝 MacBookPro-xxxx を発見しました (192.168.1.23:54321)
    チップ: Apple M2 Pro
    空きメモリ: 89.2GB / 総メモリ: 96.0GB
    ロード済みモデル: qwen2.5:14b
    インストール済みモデル(3件): qwen2.5:14b, llama3.1:8b, gemma2:9b
```

終了する場合は `Ctrl+C` を押してください。mDNSサービスの登録解除とサーバーの停止まで行われます。

### ポートを指定したい場合

```bash
python3 yoriai.py --port 8765
```

## 2台のMacで動作確認する手順

1. 両方のMacがOllamaをインストール済みで、少なくとも1つはモデルをpull済みであることを確認してください
   (`ollama pull qwen2.5:7b` など)。
2. 両方のMacが同じLAN(同じWi-Fi/有線ネットワーク)に接続されていることを確認してください。
   ※ mDNSはブロードキャストベースのため、異なるサブネットやゲストネットワーク分離のあるWi-Fiでは
   発見できないことがあります。
3. このリポジトリを両方のMacにcloneし、それぞれで依存関係をインストールします。

   ```bash
   git clone <このリポジトリのURL>
   cd yoriai
   python3 -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt
   ```

4. Mac Aで実行します。

   ```bash
   python3 yoriai.py
   ```

5. Mac Bでも同様に実行します。

   ```bash
   python3 yoriai.py
   ```

6. 数秒以内に、両方のターミナルにお互いを発見したログ(🤝 ...を発見しました)が表示されれば成功です。
   モデルをロードした状態(例: `ollama run qwen2.5:14b` を実行中)で試すと、
   「ロード済みモデル」欄に反映されることも確認できます。
7. 片方を `Ctrl+C` で終了すると、もう片方のログに「エージェントが見えなくなりました」と表示されます
   (mDNSのTTL/更新のタイミングにより、反映まで数秒〜数十秒かかる場合があります)。

### うまく発見できない場合のチェックポイント

- macOSのファイアウォールでPythonのネットワーク受信が許可されているか
  (初回実行時に許可ダイアログが出ることがあります)。
- 2台が同じサブネットにいるか(ルーターのゲストWi-Fi/クライアント分離設定に注意)。
- `ollama serve` が起動しているか(`curl http://localhost:11434/api/tags` で確認できます)。

## 実装上の判断メモ(仮決め箇所)

今回の実装で判断に迷い、ひとまずこう決めた箇所を残しておきます。次フェーズで見直す際の参考にしてください。

- **「空きメモリ」の定義**: `vm_stat` の `Pages free + Pages inactive` を空きメモリとみなしています
  (`yoriai.py` の `_parse_vm_stat_free_bytes`)。macOSは積極的にメモリをキャッシュに使うため、
  `Pages free` だけを見ると実態よりかなり少なく表示されてしまうための仮の判断です。
  より正確な「今すぐ使える空き容量」が必要になった場合は `memory_pressure` コマンドの利用も検討してください。
- **チップ情報の取得方法**: `sysctl -n machdep.cpu.brand_string` を利用しています。
  Apple Silicon Mac上ではネイティブに正しいチップ名(例: `Apple M2 Pro`)が返る前提です。
- **HTTPポート**: 既定では起動時にOSが空いているポートを自動選択します(`--port` で固定も可能)。
  複数のエージェントを1台のマシン上でテストする場合にポート衝突を避けるためです。
- **mDNSサービスインスタンス名の衝突回避**: `<ホスト名>-<agent_idの先頭8文字>` という名前で登録しています。
  同じホスト名のマシンが複数ある場合や、同一マシンで複数プロセスを起動するテストケースを想定した仮の判断です。
- **自己紹介カードの鮮度**: `/card` エンドポイントはリクエストごとにその場でメモリ/モデル情報を再取得します。
  キャッシュは行っていないため、ピア側は常に最新のスペックを取得できますが、
  多数のエージェントから同時に叩かれる状況は今回のスコープでは考慮していません。
- **認証なし**: 今回は誰でも `_yoriai._tcp.local.` を名乗れば発見・カード取得ができる状態です。
  トークンによる参加制限は次フェーズで追加予定です。
